# forge (River building), port 4612

Trains new unit types. `POST /types {name, description, dryRun?}` (`dryRun: true` forces the dry run in river mode; smoke tests must use it) starts the pipeline in `river/` (synthetic data from the brain world, SFT on River, eval vs base, serve); `GET /types` reports progress, `DELETE /types/:id` removes a (test) type. Forge units implement the Bridge API on this port: `POST /units` (the unit's type is matched by `model`, or `typeId`/`class` if sent, else the newest ready type), `POST /units/:id/send {text, orderId?, targetId?, componentId?}`, `PATCH`, `DELETE`, `GET /units`, `GET /events` (SSE). An order runs: brain /recall (emitted as `gbrain.recall` with `args.slugs`), the type's model (river/forge/serve.py child: River checkpoint, or the template voice for `dry-run:` models), brain /remember (`gbrain.remember` with `args.slug`), then `reply` (or terminal `error`), all with `orderId`.

Run: `bun run dev` (needs `river/.venv`: `cd river && uv venv --python 3.12 .venv && uv pip install --python .venv/bin/python river-client`).
Smoke: `bun run smoke` (types) and `bun run smoke:bridge` (units; needs one ready type) while the service runs.

Env: `FORGE_MODE=dry|river` (default river when `RIVER_API_KEY` is set, e.g. in `services/forge/.env` (gitignored, Bun loads it; river/forge/env.py reads the same file), else dry. Dry: real synthetic data, fake training over `FORGE_DRY_SECONDS`, default 60, model `dry-run:<id>`, evalScore null). `river` needs `RIVER_API_KEY` (set by Emre, never logged), `FORGE_BASE_MODEL`, `FORGE_TEACHER_MODEL`. `BRAIN_URL` default http://127.0.0.1:4616 (falls back to a built-in world if down).
State: `river/runs/types.json` and `river/runs/<typeId>/{train,eval}.jsonl` (gitignored).

Commander (Proposer API on this port, `PROPOSER_URL=http://127.0.0.1:4612`): `POST /propose` scores (unit, target) pairs with a small logistic model that starts at the autopilot heuristic's weights and is refit from `data/vetoes.jsonl` (`VETO_LOG`) whenever it changes (go/expired accepted, cancel rejected, adjust: original rejected and adjusted pair accepted); after 5+ decisions it holds back pairs it predicts the user would reject (p < 0.25). `GET /commander` shows veto rows, examples and learned weights. Test: `bun run test:commander` (offline).
