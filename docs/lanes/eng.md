# Team Engine: game server, mock agents, autopilot
Agents: raid-eng-plan (lead), raid-eng-impl (owns `services/engine/`), raid-eng-mock (owns `services/mock-bridge/` and `services/autopilot/`), raid-eng-rev (reviewer). Lead owns `docs/lanes/eng-plan.md`, `data/`; reviewer owns `reviews/eng.md`.
Bun + TypeScript, Hono or Bun.serve, SSE. Import shared types from `contract/types.ts` (relative import); never import another service's code.

- raid-eng-impl first step (now): `services/engine` on 127.0.0.1:4610: in-memory state per the contract, GET /api/state, SSE /api/events (state.snapshot first), POST /api/orders (unit steps tile by tile toward the target at about 3 tiles per second, then `working`, sends the order text to the bridge, `done` on reply). Seed state from the brain service GET http://127.0.0.1:4616/world, falling back to a local fixture (the contract example extended to 4 components, 6 units, 9 targets) if the brain is down. Subscribe to the bridge's GET /events (BRIDGE_URL, default mock 4615).
- raid-eng-mock first step (now): `services/mock-bridge` on 127.0.0.1:4615 implementing the Bridge API: on send, emit over 6 to 10 seconds: thinking, a `gbrain.recall` tool call, a few messages and tool calls, a `gbrain.remember` tool call, then a reply. Then `services/autopilot` on 127.0.0.1:4613: POST /propose heuristic (idle units, highest severity open target, prefer same-component history, nearest).
- M2: order prompt (issue, component, customers, and the instruction to recall from GBrain first and remember learnings after); map gbrain tool activity to memory.recall / memory.remember events; if an order finishes with no gbrain tool calls, call brain /recall and /remember as a fallback and emit the same events. `BRIDGE_URL=http://127.0.0.1:4614` works with QM.
- M3: teams and control groups (POST /api/teams, team orders), autopilot per team: ask PROPOSER_URL each few seconds for idle units of autopilot teams, emit order.proposed with vetoDeadline now + 15 s, handle cancel / adjust / go / expiry, append every resolution to data/vetoes.jsonl.
- M3/M4 Forge: `state.unitTypes`, POST /api/forge/types proxy, spawning forged types, per-unit bridge routing (FORGE_URL), `forge.updated` events (docs/CONTRACT.md, Forge API).
- M4: Barracks spawn (class to model map in one config object), stats, POST /api/reset (also calls brain /reset), robustness.
